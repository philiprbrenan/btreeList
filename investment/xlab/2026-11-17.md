# 1. Mission

### Vision

To fundamentally change the way computers process information by bringing data structures and the logic that operates
on them together onto the same piece of silicon.

Modern computers are remarkably efficient at performing arithmetic operations. They are much less efficient at moving
information between memory and processors. In many important applications, particularly database processing, searching,
indexing, financial transactions and large-scale information retrieval, the movement of data consumes more time and
energy than the computation itself.

Database on a Chip proposes a different approach.

Rather than treating memory as a passive repository of information and the processor as a separate device that
repeatedly retrieves and modifies that information, we will implement both the data structures and their associated
processing algorithms directly on the same piece of silicon.

The result will be a new class of programmable, application-specialized computing devices in which computation takes
place where the data resides.

Our initial platform will implement B-tree database structures, including the operations required to search, insert,
delete and maintain them. B-trees are particularly suitable as an initial demonstration because they are widely used,
have well-defined algorithms, involve substantial data movement in conventional implementations, and support a broad
range of practical applications.

However, the mission extends well beyond B-trees.

We intend to establish a reusable architectural and development platform through which increasingly sophisticated data
structures and their associated algorithms can be automatically translated from conventional Java code into efficient
silicon implementations.

The long-term objective is to make it practical to construct computers in which substantial portions of what are
currently software-intensive data-processing systems are implemented directly in hardware.

### Why an X-Lab is necessary

The development of Database on a Chip requires coordinated advances in algorithms, computer architecture, digital
logic, semiconductor implementation, memory technology and software tooling.

These disciplines are normally pursued in separate research and commercial environments.

Traditional computer architecture research tends to optimize processors and memory systems independently. Database
research generally assumes conventional processors and memory hierarchies. Semiconductor development focuses on
implementing established computational architectures efficiently.

Consequently, there is no natural institutional home for an effort whose primary objective is to eliminate the
architectural separation between data structures, memory and processing.

An independently operated NSF X-Lab would provide the sustained, focused engineering effort needed to investigate this
alternative architecture, develop the associated design tools, build working silicon and establish reproducible
performance measurements.

**Our mission is to make moving data the exception rather than the fundamental operating principle of computing.**

# 2. Technology Landscape

### The fundamental inefficiency

Conventional computing architectures separate processing and storage.

A processor retrieves data from memory, performs an operation and writes the result back. Complex data structures
require many such operations, frequently involving indirect addressing, comparisons, branching and repeated memory
accesses.

For database operations, this creates a substantial overhead.

For example, searching a B-tree involves traversing a sequence of branches, examining keys at each level, selecting the
next node and eventually locating the requested record.

In a conventional computer, these operations involve repeated interaction between the processor and memory hierarchy.

The resulting energy consumption includes not only the actual comparisons but also instruction processing, address
calculation, memory access, data transfer and control overhead.

Database on a Chip attacks this inefficiency at its architectural source.

Instead of moving the data to the processor, we bring the processing to the data.

### Existing approaches

Several established technologies address aspects of this problem:

- **Conventional processors:** Highly flexible and programmable, but dependent on separate memory hierarchies and
associated data movement.

- **Application-specific integrated circuits (ASICs):** Offer substantial opportunities for specialization, but
generally require significant investment in hardware design and implementation.

- **Field-programmable gate arrays (FPGAs):** Permit customized processing architectures but introduce their own area,
power and implementation constraints.

- **Processing-in-memory technologies:** Move selected computational operations closer to memory, but often retain
restrictions on the supported operations and programming models.

- **Graphics processing units:** Provide considerable parallel processing capability, but are not necessarily efficient
for irregular, pointer-based data structures and sequential search operations.

These approaches demonstrate that specialization and proximity to memory can improve computational efficiency.

However, there remains an opportunity for a more general architectural approach in which the data structures
themselves, together with their complete operational algorithms, become the primary units of hardware design which
can then be connected together with high speed Ethernet.

### The proposed platform

Database on a Chip develops a design methodology that starts with conventional, understandable algorithms and
progressively transforms them into silicon.

The existing development environment uses Java as the algorithmic specification language.

Algorithms are implemented and tested in Java, translated into Verilog, and then passed through established synthesis and physical-design tools.

This provides an important separation between the logical definition of an algorithm and its eventual physical implementation.

It also makes it possible to compare the behavior of the original algorithm and its hardware implementation.

The development platform incorporates:

1. A hardware-oriented representation of algorithms and data structures.
2. Automatic generation of Verilog from the algorithmic representation.
3. Translation of data storage requirements into appropriate hardware memory structures.
4. Integration with SRAM and ROM implementation tools.
5. Synthesis, placement and physical-design flows.
6. Automated comparison of software and hardware execution to identify functional discrepancies.

The architecture is designed to support reusable hardware components rather than requiring every new application to be
designed from the transistor level.

### Preliminary comparison with RISC-V

A preliminary comparison has been made between the specialized Database on a Chip implementation and a generic RISC-V
processor implementation using the same semiconductor technology node. Both were evaluated on the same B-tree search
task, with two or three keys per leaf or branch.

more advanced manufacturing process.

A Verilog implementation has been synthesized and physically routed, and the B-tree search operation has also been
demonstrated on an FPGA. These results establish a working basis for further investigation, although fabricated ASIC
performance and power measurements remain future work.

# 3. Outcomes

The X-Lab will investigate whether the preliminary architectural advantage can be independently validated, extended to
more demanding workloads, and generalized beyond the initial B-tree implementation.

The program will be divided into measurable stages.

### Stage 1: Establish a reproducible hardware baseline

**Target: Years 1â2**

The initial objective is to establish a complete, independently reproducible implementation of the Database on a Chip
architecture using industry-standard electronic design automation (EDA) tools. This will require access to commercial
tools from vendors such as Cadence, Synopsys and Siemens EDA, covering RTL verification, logic synthesis, physical
implementation, timing analysis, power estimation and physical verification. Appa Apps Ltd Inc. does not currently have
access to these commercial tool chains.

Deliverables:

- A complete B-tree implementation supporting search, insertion and deletion.

- Automated translation from Java to Verilog.

- Verified equivalence between software and hardware execution.

- Dedicated memory implementations using appropriate SRAM and ROM structures.

- A reproducible ASIC synthesis and physical-design flow.

- A documented reference design and benchmark suite.

The reference implementation will be compared with conventional processor-based implementations using identical datasets and equivalent operations.

Measurements will include:

- Silicon area.

- Clock frequency.

- Throughput.

- Energy per operation.

- Memory bandwidth.

- Data movement.

- Latency.

- Cost per completed operation.

A critical outcome will be a reliable measurement framework that distinguishes improvements in raw processing speed
from improvements in actual energy efficiency.

### Stage 2: Demonstrate substantial architectural advantages

**Target: Years 2â3**

The second stage will concentrate on optimizing the architecture and establishing its practical advantages.

Research will investigate:

- Alternative B-tree layouts.

- Branching factors and node sizes.

- Parallel execution of independent operations.

- Memory organization and access patterns.

- Dedicated control logic.

- Reduction of unnecessary memory transfers.

- Integration of processing logic with storage.

The target is to demonstrate at least two orders-of-magnitude improvement in energy per completed operation for
selected data-intensive workloads relative to appropriately optimized conventional implementations.

The exact targets will be refined following the Stage 1 measurements.

### Stage 3: Generalize the architecture

**Target: Years 3â5**

The third stage will extend the platform beyond B-trees.

The objective is to demonstrate that the methodology can be applied to multiple independent classes of data structures
and algorithms.

Candidate developments include:

- Hash tables.

- Other balanced search trees.

- Graph-processing structures.

- Priority queues.

- Associative lookup structures.

- Specialized indexing and retrieval engines.

The outcome will be a reusable hardware development environment connected together by high speed Ethernet rather than a
collection of unrelated ASIC implementations.

We will also investigate more sophisticated memory architectures and opportunities for greater parallelism.

### Stage 4: Approach the physical limits of efficient computation

**Target: Years 5â7**

The final stage will investigate the potential for substantially greater improvements through architectural
specialization, memory integration and alternative hardware implementation techniques.

The ambition is to contribute to the NSF objective of narrowing the gap between conventional CMOS computing and the
inherent physical limits of computation.

In particular, we will investigate whether data-centric computing can achieve improvements approaching four to five
orders of magnitude in effective computational throughput per unit of power for carefully defined classes of workloads.

This is an ambitious research target, not an asserted capability of the current implementation.

Achieving it will require more than incremental improvements in clock speed or transistor density. It will require
identifying and eliminating unnecessary computational activity and data movement at every level of the architecture.

# 5. Team Capabilities Statement

### Complementary capabilities

Database on a Chip combines an existing working software and hardware development platform with a clearly defined
architectural objective.

The project is unusual in that its central technical foundation has already been developed by its originator.

This provides a starting point for an X-Lab that can concentrate its resources on advancing and validating the
technology rather than spending its initial years defining a research concept.

The proposed team will bring together:

1. **Architectural leadership:** Definition of the overall data-centric computing architecture and its evolution.

2. **Algorithm and software engineering:** Development and verification of data structures and their translation into
hardware.

3. **Semiconductor engineering:** Optimization of logic, memory structures and physical implementations.

4. **Experimental validation:** Independent measurement of performance, energy efficiency and scalability.

5. **Commercial development:** Identification of applications, licensing opportunities and routes to adoption.

The objective is to create a small, technically focused organization with the ability to make rapid decisions and
redirect research effort in response to experimental results.

### Governance and autonomy

Initially the project will operate under an appropriate lead-organization arrangement while establishing its
technical leadership, recruitment plan, operating structure and intellectual property framework.

The intention is to establish an independently governed X-Lab capable of operating with substantial autonomy.

The X-Lab will retain direct control over:

- Technical research priorities.
- Recruitment and staffing.
- Allocation of research resources.
- Selection of external engineering partners.
- Intellectual property strategy.
- Experimental facilities and infrastructure.
- Commercialization and licensing decisions.

This autonomy is important because the project involves architectural research with uncertain outcomes. The ability to
test alternative approaches, abandon unsuccessful ideas and redirect resources is essential.

### Partnerships and commercialization

The principal commercialization opportunity is the development and licensing of hardware intellectual property and
associated design technology.

Potential customers and partners include:

- Semiconductor manufacturers.

- ASIC design organizations.

- Data-center infrastructure providers.

- Database and enterprise software companies.

- Financial technology organizations.

- Scientific computing organizations.

The commercial model will initially emphasize licensing of reusable hardware intellectual property and associated design tools, with royalties or other arrangements appropriate to individual implementations.

The X-Lab will seek partnerships with semiconductor fabrication and design organizations to support prototype manufacture, testing and eventual deployment.

The intention is not to establish another conventional semiconductor manufacturing company. It is to establish a technology organization capable of developing new computational architectures and making those architectures available to existing semiconductor and computing industries.

### Conclusion

Database on a Chip addresses a fundamental architectural limitation of modern computing.

For decades, improvements in computing have largely been achieved by making processors faster, increasing memory
capacity and improving communication between increasingly complex components.

The proposed X-Lab investigates a different possibility: eliminating much of the need for communication by making the
data structure and the computation that operates on it a single physical entity.

The existing project provides a working starting point, an established development methodology and an initial hardware
implementation.

The proposed NSF investment would allow this foundation to be developed into a substantially broader technology
platform, supported by a multidisciplinary engineering team and validated through physical silicon implementations.

**The ultimate objective is to make data-centric computing a practical alternative to conventional processor-centric
architectures, with potentially transformative consequences for the energy efficiency and economics of computing.**
